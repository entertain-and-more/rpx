## 1. Executive Summary & Value Proposition
RPX Pro (RolePlay Xtreme Professional Edition) is a comprehensive, open-source, local-first control center for tabletop pen-and-paper RPG sessions (TTRPG). Built with Python 3.10+ and PySide6 (Qt6), it unifies campaign world management, multi-map navigation, second-monitor player screen mirroring, audio/soundboard atmospheres, light effects, combat mechanics, and structured AI prompt generation into a single offline desktop application.

Key Value Proposition:
- **100% Offline & Local-First**: All campaign files, maps, characters, audio assets, and configurations remain strictly on local disk in `rpx_pro_data/`. Zero third-party telemetry, zero cloud lock-in.
- **Dual-Display Player Screen**: Dedicated second-monitor output for players showcasing interactive maps, interior/exterior location views, character party status, mission logs, and ambient light/weather overlays.
- **LLM & Agent Ready**: Headless JSON-RPC CLI (`python -m rpx_pro.app --cli`) over `stdin`/`stdout` allowing autonomous AI agents (Claude, GPT, Gemini, local models) to inspect state and automate campaigns safely.
- **Portable Campaign Bundles (`rpx-campaign-bundle-v1`)**: Zero-loss ZIP export format enabling offline viewing on tablets and phones via the static PWA companion (`web_companion/`).

## 2. Target Personas & Audiences

### [PERSONA-01] Tabletop RPG Game Masters (GMs / DMs)
- **Target Profile**: Tabletop Game Masters orchestrating in-person or hybrid RPG campaigns (D&D 5e, DSA, Pathfinder, Call of Cthulhu, or homebrew).
- **Pain Points**: Complex subscription-based VTTs requiring constant internet; managing multiple disparate apps for music, dice, character sheets, and maps; lack of a simple player-facing second screen.
- **Value Proposition**: All-in-one local session manager running offline during live games with fast map switching, atmospheric audio, and a dedicated player-facing screen.
- **Key Workflows**: Launch `python RPX_Pro_1.py`, drag-and-drop sound effects, project player screen to second monitor/TV, trigger combat rounds and environmental lighting effects.

### [PERSONA-02] Privacy-Conscious Players & Homebrew Lore Creators
- **Target Profile**: Worldbuilders, authors, and tabletop groups who prioritize absolute data privacy, local data sovereignty, and offline resilience.
- **Pain Points**: Vendor lock-in, data harvesting, server downtime during game nights, risk of losing campaign lore if a hosted VTT service shuts down.
- **Value Proposition**: Strict 100% offline, zero-network-egress design. All worlds, characters, NPC dialogues, and custom rulesets reside entirely on local disk in `rpx_pro_data/`. Transparent MIT open-source license.
- **Key Workflows**: Design custom JSON rulesets, manage characters and inventories locally, export portable `rpx-campaign-bundle-v1` ZIP files for independent offline archiving.

### [PERSONA-03] Autonomous AI Agent Engineers & LLM Tool Builders
- **Target Profile**: Developers and AI researchers building agentic RPG assistants, automated dungeon masters, NPC dialog simulators, or campaign automation bots.
- **Pain Points**: Desktop game software lacks programmatic headless APIs; graphical interfaces cannot be scripted or tested headlessly by AI agents without heavy GUI automation.
- **Value Proposition**: Standardized JSON-RPC CLI protocol over `stdin`/`stdout` (`python -m rpx_pro.app --cli`). Exposes typed API methods (`create_world`, `roll_dice`, `create_character`, `export_campaign_bundle`, etc.) for seamless agentic integration.
- **Key Workflows**: Run headless CLI sub-process, issue JSON-RPC method calls, ingest campaign state, and generate contextual story prompts across 7 AI roles with zero GUI overhead.

### [PERSONA-04] Mobile Session Companions & Tablet Users
- **Target Profile**: In-person players and travelling GMs who want to reference campaign notes, character statuses, and quest logs on iPads, Android tablets, or phones at the gaming table.
- **Pain Points**: Running full desktop VTTs on mobile devices is clunky and battery-draining; cloud mobile apps require accounts, sync servers, or internet at remote cabin sessions.
- **Value Proposition**: Zero-cloud static PWA companion (`web_companion/`). Loads local `rpx-campaign-bundle-v1` ZIP bundles with 100% client-side JavaScript, caching the shell in Service Worker for offline mobile restarts.
- **Key Workflows**: Export campaign ZIP from RPX Pro, open PWA on tablet, drag-and-drop bundle, view live party health, active missions, and world maps completely offline.

### 10 Governance & Runtime Invariants
1. **INV-LOCAL-01 (100% Offline & Local-First Zero-Egress):** All campaign data, maps, audio, characters, and configs remain strictly on local disk in `rpx_pro_data/`. Zero telemetry, zero analytics, zero external network requests.
2. **INV-USER-02 (Unprivileged User-Mode & Non-Elevation):** Operates under strict `RunAsInvoker` security without requiring administrator privileges or root access.
3. **INV-DUAL-03 (Dual-Screen State Isolation & Mirroring):** Strict isolation between the GM control dashboard and the player screen (second monitor). Hidden GM notes, monster stats, and secret locations never leak to the player view without explicit action.
4. **INV-RPC-04 (Headless JSON-RPC CLI Interface):** Zero-dependency JSON-RPC interface via `stdin`/`stdout` (`python -m rpx_pro.app --cli`) enabling programmatic AI agent interaction, unit testing, and automation without opening the GUI.
5. **INV-BUNDLE-05 (Deterministic Campaign Bundle Export):** `rpx-campaign-bundle-v1` ZIP specification with checksums and manifest validation, enabling lossless cross-platform exchange between desktop and mobile companions.
6. **INV-PWA-06 (Zero-Cloud Client-Side PWA Companion):** Static PWA web companion running completely client-side in the browser via Service Worker; restores bundles from cache offline without internet access.
7. **INV-COPYLEFT-07 (Permissive Licensing & Dynamic Linking):** Core code under MIT; PySide6 (LGPL-3.0) and pygame (LGPL-2.1) dynamically linked under LGPLv3 §4; zero copyleft contamination for user campaigns.
8. **INV-LLM-08 (Privacy-Guarded AI Prompt Generation):** AI prompt generator formats structured prompts locally across 7 specialized RPG roles; prompts are copied to clipboard or read via CLI; zero automated data transmission to cloud AI endpoints.
9. **INV-ECO-09 (Modular Sibling Ecosystem Interoperability):** Full alignment with `entertain-and-more` and `open-bricks` ecosystem (e.g. KlangpultLight sound staging, shared JSON data interchange).
10. **INV-SLA-10 (Contractual Security SLA & Multi-Platform CI):** Formal commitment to 48-hour response / 5-day triage SLA, validated by automated GitHub Actions CI matrices across Ubuntu, Windows, and macOS on Python 3.10, 3.11, 3.12, and 3.13.
